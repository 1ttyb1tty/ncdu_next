# Plan: disk-usage tree with typed categorization, timestamps, wide/simple views

## Goal
Extend ncdu-next's scan tree model with typed file categorization (kind + type), filesystem timestamps (mtime/ctime/atime), Windows file attributes, and a dual-view TUI (simple vs wide) that gracefully degrades to multi-line rows when the terminal is too narrow. All read-only; no data mutation.

## Decisions (resolved)

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Kind representation | `type kind uint8` iota enum | Narrow int, small fixed set (~11 values), memory-efficient across millions of files, zero-allocation comparisons |
| Type representation | `string` | Many possible formats (~50+), cheap to add new ones, avoids enum overflow |
| Timestamps | `mtime, ctime, atime int64` (Unix epoch ns) | Cross-platform; Windows FILETIME converted at read time |
| Windows attributes | `Attrs uint32` | FILE_ATTRIBUTE_* bitmask; 0 on non-Windows; read-only metadata only |
| View modes | `simple` (default) vs `wide`, toggle `w` | Simple = path+size (current); wide = path+size+kind+type+encoding/line-ending+mtime |
| Narrow terminal | Multi-line spillover per record | When panelWidth < wideViewMinWidth (~120 cols), each record renders across 2 lines |
| Size units | bytes → KiB/MiB/... → kB/MB/... cycle via `u` | Integer-only, no floats; header shows unit family |

## Tree node additions

`tree.Node` gains:
- `Kind kind` (uint8 enum) — broad category
- `Type string` (unchanged) — specific format/extension
- `Encoding string`, `LineEnding string` (existing)
- `Mtime, Ctime, Atime int64` — Unix epoch nanoseconds
- `Attrs uint32` — Windows FILE_ATTRIBUTE bitmask; 0 on non-Windows

### Kind enum (uint8 iota)
```
kindUnknown = 0
kindDiskImage = 1
kindContainerImage = 2
kindMemoryState = 3
kindOfficeDoc = 4
kindImage = 5
kindAudio = 6
kindVideo = 7
kindText = 8
kindSource = 9
kindMarkup = 10
kindOther = 11
```

`Type` strings unchanged (e.g. `vdi`, `qcow2`, `go`, `md`). Every scanned node carries both `Kind` and `Type`; export round-trips both as JSON (`kind` numeric, `type` string).

## Size units & formatting (`--detect-format` not required)

Sizes are displayed per-tab with an integer-only unit mode; no floating-point
formatting is used. The mode is per-tab and toggled with `u`, cycling:

```
bytes → IEC binary → SI decimal → bytes
```

| Mode | Unit suffixes | Base | Header label above size column |
|------|---------------|------|--------------------------------|
| bytes | plain integer count | 1 | `bytes` |
| IEC binary | KiB, MiB, GiB, TiB, PiB, EiB | 1024 | `KiB/MiB/GiB` |
| SI decimal | kB, MB, GB, TB, PB, EB | 1000 | `kB/MB/GB/TB` |

Values smaller than 1 unit show as a plain byte count. Larger values are
rounded to the nearest whole unit (round half up) with the corresponding
suffix; every size value carries its unit suffix and the column header shows
the current unit family.

## Wide vs simple view

`--listen` TUI adds `w` key toggling per-tab `viewMode` (simple|wide).

Simple (default): `path size` — current behavior.
Wide: `path size kind type encoding line-ending mtime` (each column aligned).

When `panelWidth < wideViewMinWidth` (~120), each record renders across 2 lines:
```
<name>    <size>   <kind>
   <type>   <encoding> <line-ending> <mtime>
```
Timestamps formatted as `YYYY-MM-DD HH:MM`.

## Windows attributes
`Attrs uint32` = FILE_ATTRIBUTE_* bitmask on Windows; 0 elsewhere. Displayed in wide view as attribute letters (R/H/S/A/RP/...) or omitted when 0.

## Data flow

**Live scan:** `Walker.Scan()` walks tree; per file, `detectFileType` sets `Type`; `Type` derived into `Kind`; `os.FileInfo` provides ModTime/access/creation (platform-specific) → `Mtime`/`Ctime`/`Atime`; Windows file attributes → `Attrs`. Each node carries `Kind`+`Type`+timestamps+`attrs`+`Size`.

**Watch-only / export:** `export.Read` loads tree incl. all fields; JSON round-trips all fields.

**TUI:** `--listen` TUI shows simple view by default; `w` toggles wide; `u` toggles size units; width/height from terminal; narrow terminal → 2-line rows.

## Failure modes
- Unknown extension → `Type=""`, `Kind=kindOther`; scan continues
- Stat read fails → keep extension `Type`, leave timestamps/attrs zero, log verbose, continue
- Terminal narrower than panelWidth → 2-line row spillover (no crash)
- `export.Read` on file missing new fields → fields default to zero/`""`

## Rollback
- Entirely additive; existing single-tab/simple behavior preserved when `--listen` not used or wide not toggled
- No config schema changes; no migration

## Timestamp storage optimization (v2.5/v3)

Timestamps are stored as int64 Unix epoch nanoseconds on every node. For very
large trees this is a significant per-node cost. Investigate for v2.5/v3:
- Coarsen resolution (e.g. millisecond or second precision) if sub-second
  precision is not needed for display.
- Delta-compress timestamps against a per-tree base time (e.g. scan start
  time) so most values become small integers.
- Sort/delta-compress by path locality so consecutive timestamps are small.
- Pack timestamps into a separate compressed columnar block rather than an
  int64 per node.

Decide in v2.5/v3 based on measured memory pressure; do not implement in v1.
