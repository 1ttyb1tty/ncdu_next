# Plan: optional ultra-compact web mode for ncdu-next

**Goal:** Add a read-only, optional, built-in web server (LAN-capable) that serves disk-usage tree data as a self-contained browser UI, gated behind an explicit `--listen` flag and mutually exclusive with the bubbletea TUI.

## Decisions (resolved)

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Integration mode | `--listen addr` replaces the TUI for that run; never runs alongside | Simple startup, no conflict |
| Data freshness | One-shot scan at server startup; no `/api/rescan` endpoint in v1 | Matches existing scan semantics; no concurrency/state needed |
| UI delivery | Embedded SPA (`//go:embed` HTML/JS/CSS) + JSON API | Zero client setup; SPA doubles as machine API |
| Default bind | localhost-safe default; `--listen 0.0.0.0:8080` explicit opt-in for LAN | Trust boundary; read-only by construction |
| Watch-only mode | `--watch-only` skips live scan; loads tree from `--export` JSON as input | "Both" modes; read-only replay without scanning |
| `--export` flag | Dual-purpose: output path in live mode; input path in watch-only mode | Minimal flag surface |
| Write endpoints | None in v1 (no delete/trash) | Trash/deletion is a v2 high-risk candidate; web stays read-only |
| Mutex with `--export` (live) | `--export` + `--listen` both allowed: scan -> write JSON -> serve | Optional headless artifact alongside server |

## Scope boundaries

**In scope (v1):**
- `cmd/ncdu-next/main.go`: add `--listen` and `--watch-only` flags; wire web server in place of TUI when `--listen` set
- New package `internal/web` (or `internal/ui/web`): embedded SPA + HTTP handlers
- JSON API: `GET /api/tree` returns serialized `export.Entry`; `GET /api/health` liveness
- Static SPA served at `/` from `internal/web/static/` (embedded)
- Watch-only: load tree via `export.Read` from `--export` path; skip `scan` entirely
- Live mode: one-shot scan -> optional `--export` write -> serve
- Bind address/port parsed from `--listen` (`host:port`); default listen addr TBD (localhost:8080 recommended)

**Out of scope (v1):**
- `/api/rescan`, live re-scan, polling updates
- Delete/trash/write endpoints
- `--watch-only` with `--export` missing -> error (flag validation)
- `--listen` + TUI coexistence (revisit later)
- Authentication/TLS (read-only LAN tool; trust boundary documented)
- Observer long-term watching of filesystem changes

## Affected files / new files

- `cmd/ncdu-next/main.go` — flag wiring, mode dispatch (live/watch-only/web/TUI/export)
- `internal/web/` (new package) — HTTP server, route handlers, embedded static assets
- `internal/web/static/index.html` (new) — SPA shell
- `internal/web/static/app.js` (new) — fetches `/api/tree`, renders tree view
- `internal/web/static/style.css` (new) — minimal styles
- `internal/config/config.go` — no structural change needed (flags live in main.go; add `Listen`/`WatchOnly` fields only if config persistence desired — defer)
- `internal/scan/` — unchanged
- `internal/tree/` — unchanged
- `internal/export/` — unchanged (`FromNode`, `Write`, `Read` reused)

## Data flow

**Live mode (`--listen H:P`, no `--watch-only`):**
1. Load config (existing path)
2. `scan.New(...).Scan()` -> `*tree.Node` (one-shot)
3. If `--export` set: `export.Write(path, node)` (optional artifact)
4. Start HTTP server on `H:P`; `GET /api/tree` -> `export.FromNode(node)` JSON
5. Serve embedded SPA at `/`

**Watch-only mode (`--listen H:P --watch-only`):**
1. Require `--export` path (validate present; error otherwise)
2. `export.Read(path)` -> `*tree.Node`
3. Start HTTP server on `H:P`; serve `/api/tree` from loaded node
4. No `scan` invocation

**TUI mode (default, no `--listen`):** unchanged existing behavior.

**Export-only mode (`--export FILE`, no `--listen`):** unchanged existing behavior.

## Failure modes & handling

- `--watch-only` without `--export`: error at flag validation, exit non-zero before server starts
- `--watch-only` with unreadable/missing `--export`: `export.Read` error -> log + exit non-zero
- Port already in use: `http.ListenAndServe` error -> log + exit non-zero
- Scan error in live mode: existing `w.Scan()` error path (log + exit non-zero)
- SPA asset missing: `embed.FS` lookup failure -> 500 on `/`; mitigated by `go generate`-style embed at build time
- Concurrent access to in-memory tree: read-only after construction; no mutex needed (tree not mutated post-scan)

## Rollback / rollout

- Feature entirely opt-in (`--listen` required); existing `go build ./...`, `go test ./...`, TUI, and export paths unchanged
- If web code fails to compile or tests fail, removing `internal/web/` and reverting `main.go` flag wiring restores prior behavior
- No config file schema changes; no migration

## Validation plan

1. `go build ./...` compiles including `internal/web`
2. `go vet ./...` clean
3. `go test -count=1 -race ./...` all pass (existing tests unchanged; add `internal/web` tests)
4. Manual: `ncdu-next --listen 127.0.0.1:8080 .` -> open `http://127.0.0.1:8080`, SPA loads, `/api/tree` returns JSON matching scan output
5. Manual: `ncdu-next --export /tmp/tree.json --listen 127.0.0.1:8081 .` -> JSON artifact written and server serves it
6. Manual: `ncdu-next --watch-only --export /tmp/tree.json --listen 127.0.0.1:8082` -> serves without scanning (no disk read beyond the JSON file)
7. Manual: `ncdu-next --watch-only --listen 127.0.0.1:8083` (no `--export`) -> non-zero exit, clear error
8. LAN: `ncdu-next --listen 0.0.0.0:8080 .` reachable from another machine on same network
9. Mutual exclusion: `--listen` with no path -> scan current dir; no TUI spawned
